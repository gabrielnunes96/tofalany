Origem

Demanda to-falando-v1: RF-1a, RN-1, CA-1a; risco R-6 (link no AppImage).

Padrão

Técnica §3 (GET /convite/:codigo, GET /downloads/:arquivo) e §6.

Implementação (05/11/2026, commit ea65248)

  • Página do convite: /convite/<código> com downloads (só .exe, .AppImage, .deb da pasta DOWNLOADS), botão "Abrir no ToFalany" (tofalany://convite?servidor=…&codigo=…) e servidor e código para digitar; código errado dá 404; limite de tentativas por IP (429), igual ao do cadastro; CSP restrita, HTML escapado, sem cache.
  • Link copiável: qualquer membro recebe o link no ola e em convite:atualizado (montado com URL_PUBLICA, ou X-Forwarded-* atrás do proxy, ou o host); botão "Copiar link de convite" (clipboard do processo principal), aviso some em 4 s.
  • Abrir pelo link: instância única por pasta de dados; a segunda instância repassa o link e sai sem abrir nada; link que chega antes do renderer fica guardado. Só o app empacotado se registra no sistema (o registro no .deb/.exe/AppImage é da T24).
  • Segurança do convite no app: com sessão no mesmo servidor, só entra; senão abre o cadastro com o código sem trocar o servidor salvo (só vira padrão depois de entrar), com "Cancelar convite"; servidor fora do ar mostra "Sem conexão" e "Tentar de novo" mantém o convite.
