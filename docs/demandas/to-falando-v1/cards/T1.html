Origem

Demanda to-falando-v1, RF-1 e CA-1: na primeira execução o app pede a URL do servidor, testa a conexão e a guarda; URL inacessível mostra erro e não avança.

Padrão

Monorepo npm (shared, server, client) conforme a técnica §2; Electron com contextIsolation, sandbox e sem nodeIntegration; configurações locais em userData validadas no processo principal.

Implementação (04/11/2026, commit a26d78d)

  • Rota/contrato: GET /api/servidor → { app: "tofalando", nome, versao, limiteContas } (o campo contas entra na T2); GET /api/saude → { ok }. CORS liberado (autenticação será por token).
  • Servidor: Fastify 5, configuração por variáveis de ambiente (PORTA 1–65535, HOST, NOME_SERVIDOR, LIMITE_CONTAS padrão 20, LOG).
  • App: Electron 45 + React 19 (electron-vite). Tela "Endereço do servidor": normaliza (sem esquema assume http://), testa em /api/servidor com tempo limite de 5 s e só guarda se for um servidor ToFalany. "Trocar servidor" com "Cancelar"; o endereço anterior só é substituído quando o novo passa no teste.
  • Segurança do Electron: corretor ortográfico desligado, links externos no navegador do sistema, navegação da janela bloqueada, pasta de dados de teste só fora do app empacotado.
  • Fora desta tarefa: CSP (T23); tela após conectar é provisória até o login (T2).

Testes
